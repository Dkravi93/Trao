# Trao AI Interview Prep Kit

Trao turns a job description and company URL into an interview preparation kit: extracted role requirements, company research, interview questions, flashcards, coverage reporting, and a day-by-day study schedule.

## Architecture

- `src/app`: Next.js client UI for authentication, kit creation, practice, and builder editing.
- `src/api`: Express API with MongoDB persistence, cookie-based access and refresh sessions, and ownership-scoped kit routes.
- `src/application/generate-kit.ts`: composition root shared by the web API and CLI evaluator.
- `src/domain`: Zod kit contract, schedule allocation, and deterministic coverage checks.
- `src/retrieval`: SSRF-aware company crawling and interview-discussion retrieval.
- `src/generation`: optional LLM extraction/generation with deterministic fallbacks.

## Local setup

Install dependencies with `npm install`. Set `MONGODB_URI` and a `SESSION_SECRET` of at least 32 characters before starting the API. Optional LLM settings are read from the provider-specific environment variables in `src/generation/llm-client.ts`.

Run the services in separate terminals:

```text
npm run start:api
npm run dev
```

The API defaults to `http://localhost:4000`; the web app defaults to `http://localhost:3000`. Set `NEXT_PUBLIC_API_URL` and `CORS_ORIGIN` when they differ.

## Builder behavior

Questions, flashcards, and the company brief have optional `pinned` state. Inline edits and manually added items set `pinned: true`. Question and flashcard edits, additions, deletions, and question array reorder/category updates are scoped to the owning kit and validated against the complete kit contract.

Section regeneration is available for the company brief, an individual question category, and the schedule. Regenerating a category replaces only unpinned questions; pinned questions survive. A pinned company brief requires explicit confirmation before replacement. Schedule regeneration recalculates allocation and coverage from the current question set.

The existing whole-kit `PUT /kits/:id` remains available for trusted complete-kit updates. Builder routes return the updated public kit so clients can refresh immediately.

## Verification

```text
npm run build
npm test
npm run evaluate -- --input examples/cases.json --output examples/kits.json
```

The evaluator processes cases concurrently and records per-case failures instead of aborting the whole run. Retrieval and LLM calls can still be slow or unavailable; the generation path logs failures and uses deterministic fallbacks where implemented, while hard retrieval failures are reported in the result.

## Known limitations

- The current UI uses browser prompts for manually adding questions and flashcards; richer forms would improve validation and usability.
- Schedule day focus text is generated by the allocator and is not independently editable.
- Regeneration depends on the live company URL and provider availability.
- Deployment is environment-specific. The repository does not contain hosted frontend/API URLs, hosting manifests, or infrastructure configuration, so public reachability must be verified after deployment with `/health` and the web URL.
